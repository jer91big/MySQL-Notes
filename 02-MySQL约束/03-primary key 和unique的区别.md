不是错觉！而且你发现了一个很重要的知识点。

**唯一约束（UNIQUE）和主键约束（PRIMARY KEY）确实非常相似。**

它们都是 MySQL 常见约束家族中的成员，六种约束的总览见 [[01-常见约束]]。

它们都有一个共同点：**保证字段中的数据不能重复。**

但两者的定位不同。我们用一个学生表来理解。

## **一、先看相同点**

假设有一张学生表：

```sql
CREATE TABLE student (
    id INT PRIMARY KEY,
    phone VARCHAR(20) UNIQUE,
    name VARCHAR(20)
);
```

这里：

- `id` 使用主键约束。
    
- `phone` 使用唯一约束。
    

它们都不允许重复。

例如：

|id|phone|name|
|---|---|---|
|1|13800138000|张三|
|2|13800138001|李四|
|3|13800138002|王五|

如果再插入一条 `id = 1` 的数据，会失败。

如果再插入一条 `phone = 13800138000` 的数据，也会失败。

所以你觉得它们相似，完全正确。

## **二、真正的区别**

重点来了，记住下面三个区别：

|对比|PRIMARY KEY|UNIQUE|
|---|---|---|
|是否允许重复|不允许|不允许|
|是否允许 NULL|不允许|允许|
|每张表可以有几个|只能有一个主键约束|可以有多个唯一约束|

### **区别1：NULL**

主键不允许 NULL。

```sql
id INT PRIMARY KEY
```

下面这种数据不允许：

```sql
INSERT INTO student (id, phone, name)
VALUES (NULL, '13800138000', '张三');
```

但是唯一约束允许 NULL：

```sql
phone VARCHAR(20) UNIQUE
```

可以有多条记录的 phone 为 NULL。

注意：NULL 表示未知或缺失，不等于普通的重复值。

### **区别2：一个表可以有几个？**

假设学生表中有：

- 学号
    
- 手机号
    
- 身份证号
    
- 姓名
    

其中学号、手机号、身份证号都要求唯一。

那么可以这样设计：

```sql
CREATE TABLE student (
    id INT PRIMARY KEY,
    phone VARCHAR(20) UNIQUE,
    id_card VARCHAR(30) UNIQUE,
    name VARCHAR(20)
);
```

这里：

- 主键只有一个：`id`
    
- 唯一约束有两个：`phone` 和 `id_card`
    

为什么？

因为一张表只能有一个主键约束，但可以有多个唯一约束。

## **三、用生活中的例子记忆**

**主键 PRIMARY KEY**

身份证号码：每个人必须有，不能重复，也不能缺失。

**唯一约束 UNIQUE**

手机号：不能和别人重复，但可以没有填写。

当然，这只是帮助记忆的例子，现实中手机号也可能发生变更。



**最后记住一句话：主键一定唯一，唯一约束不一定是主键。** 这就是它们最核心的区别。
