字符串函数是**逐行加工**（100 行进去，100 行出来）；聚合函数则是**多行汇总**（一叠账单塞进去，吐出一个汇总指标）。这一篇把聚合函数和分组查询放在一起学，因为它们几乎总是配合出现。

查询基础见 [[SELECT查询]]，字符串函数见 [[字符串函数]]。

### 1. 聚合函数：把整堆数据榨成几个关键数字

| 函数 | 动画形象 | 作用与 `NULL` 小细节 |
| --- | --- | --- |
| `COUNT(*)` | 计数器“咔哒咔哒”数人数 | 统计**行数**（不关心某一列是否为 `NULL`）；`COUNT(列名)` 只数该列**非 `NULL`** 的个数 |
| `SUM(列)` | 大漏斗把数字全倒进同一个水桶求和 | 计算数值列总和，自动忽略 `NULL` |
| `AVG(列)` | 先算总和再除以有效份数求平均 | 计算数值列平均值，**自动忽略 `NULL`**（不把 `NULL` 当 `0` 算进分母） |
| `MAX(列)` | 跳高冠军标尺，挑出最高值 | 最大值（数字、日期、字符串都能比），忽略 `NULL` |
| `MIN(列)` | 俯卧撑底线标尺，挑出最低值 | 最小值，忽略 `NULL` |

```sql
SELECT
  COUNT(*) AS 总人数,
  COUNT(score) AS 已出分人数,
  AVG(score) AS 平均分,
  MAX(score) AS 最高分,
  MIN(score) AS 最低分,
  SUM(score) AS 总分
FROM students;
```

注意：`COUNT(*)` 和 `COUNT(score)` 的结果可能不同——前者数所有行，后者只数 `score` 不为 `NULL` 的行。

### 2. `GROUP BY` + `HAVING`：先分小组再算账

全校平均分只有一个数字，但如果我们想知道**每个班各自的平均分**，就需要先按班级把学生**分成不同小组**，再在每个小组里跑聚合函数——这就是 `GROUP BY`：

```sql
SELECT
  class_name AS 班级,
  COUNT(*) AS 人数,
  AVG(score) AS 班均分
FROM students
WHERE score IS NOT NULL
GROUP BY class_name
HAVING AVG(score) >= 85;
```

**动画画面**：

1. 先用 `WHERE` 把没出成绩的剔除（**分组前过滤单行**）；
2. `GROUP BY class_name` 吹哨分队：`'CS1'` 一队、`'CS2'` 一队……每个队独立算出 `COUNT(*)` 和 `AVG(score)`；
3. `HAVING AVG(score) >= 85` 像**小组赛晋级线**：只留下班均分达到 85 分及以上的班级小组。

**`WHERE` vs `HAVING` 核心区别**：

- **`WHERE` 在分组之前**：过滤的是**单条原始记录**，里面**不能**直接用聚合函数（如 `SUM`、`AVG`）。
- **`HAVING` 在分组之后**：过滤的是**分好组后的聚合结果**，专门用来筛分组统计条件（如 `HAVING COUNT(*) >= 5` 或 `HAVING AVG(score) >= 85`）。

#### 小叮咛：`SELECT` 后面能写哪些列？

在 MySQL 默认的 `ONLY_FULL_GROUP_BY` 模式下，`SELECT` 后面出现的列，要么出现在 `GROUP BY` 中，要么被聚合函数包起来。比如：

```sql
-- 正确：class_name 在 GROUP BY 中，score 被 AVG 包起来
SELECT class_name, AVG(score)
FROM students
GROUP BY class_name;
```

```sql
-- 错误：name 既不在 GROUP BY 中，也没有被聚合函数包起来
SELECT class_name, name, AVG(score)
FROM students
GROUP BY class_name;
```

### 3. 在完整查询中的位置

加入分组后，查询的执行顺序是：

`FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY` → `LIMIT`

所以 `WHERE` 只能过滤原始行，`HAVING` 专门过滤分组后的结果，聚合函数是在分组之后才计算的。完整的执行顺序动画见 [[SELECT查询]]。
