现在进入 **SQL 函数** 的世界！你可以把**函数**想象成档案管理员随身携带的**一个个微型魔法加工机**：你把原始数据（比如一段乱糟糟的姓名、一串带空格的编号、一句长长的备注）塞进加工机的**输入槽**，机器“咔咔”运转一下，吐出加工好的新结果。注意：**函数通常只是在查询或计算时“临时加工出新值”，不会直接把原表里的原始数据擦掉（除非你配合 `UPDATE` 写回去）**。

今天我们先拆开第一台加工机——**字符串函数（String Functions）**。在档案室里，文字最容易出现大小写不统一、前后多出空格、字段需要拼接或截取的情况，字符串函数就是专门治这些“文字小毛病”的法宝！

### 1. 大小写变身机：`UPPER` 与 `LOWER`

档案室里登记员工邮箱或工号时，有人写 `alice@example.com`，有人写 `ALICE@EXAMPLE.COM`，还有人写 `Alice@Example.com`。如果你想统一比对或展示，就可以请出大小写变身机：

- **`UPPER(str)`**：把字母全部吹成**大写**。
- **`LOWER(str)`**：把字母全部压成**小写**。

SQL

```sql
SELECT
  email,
  UPPER(email) AS upper_email,
  LOWER(email) AS lower_email
FROM employees;
```

**动画画面**：原始邮箱像一排高低错落的积木，`UPPER` 像一阵向上吹的强风把字母全吹成大写，`LOWER` 像一台压平机把字母全压成小写。在做大小写不敏感的搜索或清洗数据时，把两边都包一层 `LOWER(...)` 非常常见。

### 2. 吸尘修剪器：`TRIM`、`LTRIM` 与 `RTRIM`

录入数据时，手滑多敲几个空格是家常便饭，比如 `' 张三 '`。如果直接用 `WHERE name = '张三'` 去匹配，安检门可能会因为那几个看不见的空格而拒之门外！这时候就需要吸尘修剪器：

- **`LTRIM(str)`**：只吸掉左边（Left）开头的空格。
- **`RTRIM(str)`**：只吸掉右边（Right）末尾的空格。
- **`TRIM(str)`**：**左右两边**的空格一起吸干净。

SQL

```sql
SELECT
  name,
  LENGTH(name) AS raw_len,
  LENGTH(TRIM(name)) AS clean_len
FROM students
WHERE TRIM(name) = '张三';
```

**动画画面**：一把小吸尘器顺着文字边缘“滋溜”一吸，前后的空气空格瞬间被卷走，只剩下实打实的字符。有些 SQL 方言（如 MySQL）还支持指定修剪字符，比如 `TRIM(BOTH 'x' FROM 'xxhelloxx')` 会把两头的 `'x'` 剪掉。

### 3. 精准剪刀与尺子：`SUBSTRING` / `SUBSTR`、`LEFT`、`RIGHT` 与 `LENGTH` / `CHAR_LENGTH`

有时候，整串字符里我们只要其中一小段——比如从身份证号或订单号里提取前缀、年份或尾号。先用尺子量一量长度，再用剪刀剪下来：

- **量长度**：
    - **`CHAR_LENGTH(str)`**（或在 MySQL 中常用的 **`LENGTH(str)`**，注意不同方言对多字节字符/中文的统计细节略有差异：MySQL 中 `CHAR_LENGTH` 按字符数算，`'你好'` 是 `2`；`LENGTH` 按字节数算，在 UTF-8 下 `'你好'` 通常是 `6`）。
- **剪片段**：
    - **`SUBSTRING(str, start, length)`**（很多数据库也支持简写 **`SUBSTR(str, start, length)`**）：从第 `start` 个位置开始，剪出 `length` 个字符。**注意：在标准 SQL 和 MySQL 中，字符串下标通常是从 `1` 开始数起，不是从 `0` 开始！**
    - **`LEFT(str, n)`** / **`RIGHT(str, n)`**：直接从最左边或最右边剪出 `n` 个字符。

SQL

```sql
SELECT
  order_code,
  LEFT(order_code, 3) AS prefix,
  SUBSTRING(order_code, 5, 4) AS year_part,
  RIGHT(order_code, 2) AS suffix
FROM orders;
```

**动画画面**：管理员拿出一把带刻度的透明尺子贴在 `order_code` 上，从第 5 格开始数 4 格，咔嚓一剪，精准抽出一小块拼图。

### 4. 胶水拼接机：`CONCAT` 与 `CONCAT_WS`

档案室里原本把 `last_name`（姓）和 `first_name`（名）分两列存着，现在报表要求拼成一句完整的称呼，比如 `张 三` 或 `张-三`。这就轮到胶水拼接机出场了：

- **`CONCAT(s1, s2, ...)`**：把多段字符串按顺序粘在一起。
- **`CONCAT_WS(separator, s1, s2, ...)`**：带分隔符（With Separator）的胶水，自动在每两段之间抹上指定的连接符号（比如 `'-'` 或 `', '`）。

SQL

```sql
SELECT
  CONCAT(last_name, first_name) AS full_name,
  CONCAT_WS('-', department, role, emp_code) AS badge_id
FROM employees;
```

**动画画面**：`CONCAT` 像把几块积木涂上胶水首尾相接；`CONCAT_WS` 更贴心，每接一块积木前自动刷一层分隔线，省得你手动写一堆逗号和连接符。

> **小心 `NULL` 吞噬效应！** 在不少 SQL 环境中，如果 `CONCAT` 里的某一段是 `NULL`（表示“未知/空缺”），整条拼接结果可能会变成 `NULL`；而 `CONCAT_WS` 通常会聪明地跳过 `NULL` 值，只拼接非空的部分，这一点在写查询时非常实用。

### 5. 替换喷漆枪：`REPLACE`

如果发现某类老旧编码里的前缀写错了，比如想把 `'OLD-'` 统一换成 `'NEW-'`，不用一行行手动改，用替换喷漆枪扫一遍即可：

SQL

```sql
SELECT
  sku,
  REPLACE(sku, 'OLD-', 'NEW-') AS updated_sku
FROM products;
```

**动画画面**：一把喷漆枪沿着字符串扫描，只要遇到匹配的 `'OLD-'`，就喷上一层 `'NEW-'` 覆盖掉，没匹配到的部分原封不动。

### 6. 组合拳实战：把加工机串成流水线

在真实的 SQL 查询里，这些字符串函数往往不是单打独斗，而是像**工厂流水线**一样嵌套在一起：先去空格、再转大写、再截取或拼接：

SQL

```sql
SELECT
  student_id,
  UPPER(TRIM(email)) AS clean_email,
  CONCAT(TRIM(name), '（', RIGHT(student_id, 4), '）') AS display_label
FROM students
WHERE UPPER(TRIM(email)) LIKE '%@SCHOOL.EDU';
```

**动画画面**：数据从 `students` 表出发，先经过 `TRIM` 吸掉多余空格，接着 `UPPER` 统一大小写，最后 `CONCAT` 和 `RIGHT` 拼出整整齐齐的展示标签，整个过程行云流水。

不同数据库方言（如 MySQL、PostgreSQL、SQL Server、Oracle）在个别函数名或 `NULL` 处理细节上会有细微差别，但核心思路完全相通——先看清你要把原始字符串变成什么样，再挑出最顺手的那台“加工机”。
